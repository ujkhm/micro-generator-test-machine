# 安全電流模組總架構（實作備忘，無程式碼）

適用：micro generator 韌體；有刷機當發電機。  
前提：主動力已能定速；發電側由 INA232 讀電壓／電流；本模組負責「找出連續安全電流」並在之後當硬上限。  
實作時再寫程式。本文只定流程、對接方式、彈性設定與安全邊界。

**2026-10-06**：通過條件改為銅溫升，不再用電流下垂。每一檔 \(R_{th}=(k_e n-V)/I\)，\(k_e\) 取該檔開路；第一檔轉速拉回後的 \(R_{th}\) 為冷態基準。溫升 \(\Delta T=(R_{th}/R_0-1)/0.00393\) 達到 `SAFE_WINDING_RISE_MAX_C`（40°C）即停，用上一通過檔。轉速未拉回前不判定熱穩；轉速停滯則視為主動力極限，不再空等後續檔。

**2026-08-27 硬體變更**：發電機到 INA232 之間串了一顆 SS54 蕭特基二極體防反接。電流讀值不受影響(判斷通過/上限的下垂比例、硬電流天花板都以電流為準，完全不用改)；本模組唯一會讀的電壓量(`safe_oc_voltage_V`)已在韌體端補償二極體順向壓降，代表發電機端子的真實 Voc，見 `settings.h` 的 `ss54_compensate_voltage_V()`。

---

## 1. 模組要做什麼

兩件事，同一個模組，兩個階段：

1. 識別：負載電阻固定，只改轉速，每個轉速長期定住，用輸出電流是否還在掉、以及硬上限，找出連續安全電流 I_cont。
2. 守護：識別結束後（或已從記憶體讀到舊值），任何發電側電流超過 I_cont（再加一層硬天花板）就立刻切斷負載並走既有故障鎖定。

測到的 I_cont 是「這顆測試電阻、這套散熱、這條 I 約正比於轉速的負載線」上的連續電流，不是銘牌上處處通用的額定電流。允許把它當後續所有轉速／負載的保守天花板。換電阻或換散熱要重測。

I_cont 要發布給極限轉速模組當 I_allow（與硬電流取較嚴）。安全電流識別期間極限轉速只有「硬電流算出來的暫定 n_lim」；I_cont 產出後極限轉速會重算並收緊。本模組階梯讀暫定 n_lim，不要等 I_cont 才開始（否則互相等）。

不測扭矩、不算效率、不掃可變電阻、不在識別中追求最大功率點。高轉若公式顯示最大功率點電流已大於當前上限，該轉速只准開路或極輕載，不准把負載接到最大功率。

## 2. 物理方法（精簡）

固定電阻時，電壓與電流不是兩個獨立資訊（電壓約等於電流乘電阻）。長期定速能看到的是：電機變熱 → 內阻上升、磁鐵變弱 → 同一轉速電流慢慢下降。

判讀：

- 電氣先穩（毫秒～數十毫秒），再等熱穩（小馬達殼側常見十到二十分鐘）。
- 熱穩後，電流相對「電氣剛穩那一小段」只掉約百分之二到三、且已不再掉：這一檔通過，電流可當偏安全的連續值。
- 掉約百分之五到十才打平：當上限，取「上一檔通過」的穩態電流當 I_cont，本檔不當通過。
- 一直掉、不平、或碰到硬電流／硬電壓／飛車／無脈衝：立即斷負載，本檔失敗。

可選加強：熱穩後短暫切斷負載、量開路電壓（數秒內，別等它冷掉），再合上。用開路電壓與帶載電流估算熱態內阻，換算銅線溫升。沒做這一刀，就不要宣稱量到繞組溫度，只宣稱量到電流下垂。

殼溫若以後有感測器可當輔助門檻（例如環境以上四十度就停）。沒有溫度感測時，以電流下垂與硬電流上限為準。主動力馬達的熱會經聯軸器傳到發電側，殼溫不可當成發電繞組的唯一依據。

由低轉往上加一檔，兩檔之間若電機還很熱，要等冷回（或規定最短冷卻時間），否則熱會累積、看起來比較不耐流。I_cont 取最後一個「完全通過」檔的熱穩電流，不是失敗檔當下的電流。

## 3. 在整機裡的位置

本模組不驅動主動力 PWM，不讀光柵，不直接操作 INA232 匯流排。

- 讀：轉速穩調旗標、現在轉速、目標轉速、故障、INA 電壓電流是否有效、UI 是否已在運行。
- 寫：自己的狀態與識別結果；要換轉速時只改目標轉速，然後等穩調旗標再量。
- 切：發電側接到測試負載的 GPIO（若啟用）。預設斷開＝開路＝安全。任何故障、急停、識別結束、上電瞬間，負載都必須是斷開。
- 故障：與現有測速／PID 同一套鎖定（斷主動力 PWM、需重開機）。斷負載必須發生在鎖定當下，不可等下一個迴圈。

啟動時機：按 START、主動力定速且穩調旗標為真、且未在自動調參之後。調參期間本模組只許保持負載斷開。按 START 當急停時，本模組與其他人同一條急停路徑，先斷負載。

任務建議：Core 1、優先權低於畫面、高於 Arduino 迴圈；週期不必快（識別時數百毫秒輪詢即可）。守護電流若擔心週期太慢，可在 INA 任務裡只做「超硬上限就升起旗標」，本模組或急停路徑負責斷負載。不要在 INA 任務裡做長時間狀態機。

## 4. 對接 settings.h 資料中樞

完全照現有模組抄：

- 在 settings 宣告本模組自己的結構體，執行期狀態與識別結果放這裡。
- 在 settings 原始碼檔加一顆專用自旋鎖，與測速、PID、INA、UI 分開，避免量測卡住控制迴路。
- 每個純量欄位用既有巨產生執行緒安全的讀寫函式。跨模組只准用這些函式，不准直接碰別人的欄位。
- 一次要寫「負載已切斷＋識別失敗＋故障碼」這種彼此相關的事實，用既有的鎖守衛包住自己結構的整段；需要同時改測速側故障鎖定時，遵守「同一時間只持一顆鎖」：先改完自己的結構並解鎖，再呼叫測速側既有的故障／急停流程，或由主程式統一急停、本模組只提供「請切斷負載」的函式給急停呼叫。
- 鎖內只能幾行欄位讀寫。禁止在鎖內做序列埠、延時、快閃記憶體。要存識別結果：先在鎖內複製到區域變數，解鎖後再寫入（寫法對齊 PID 的載入／儲存）。
- 新增故障碼（例如發電過流、識別超溫／電流下垂超標、負載 GPIO 未就緒、INA 在識別中掉線）。這些碼與現有飛車、無脈衝、急停並列，鎖定後同樣要重開機。
- 識別用的常數（電阻歐姆、轉速階梯、下垂百分比、熱穩時間、硬電流）放 settings 檔開頭的常數區，與飛車轉速、分流電阻同一層，方便改機台時只改一處。
- 腳位放腳位檔：負載接通 GPIO 與主動力 PWM、測速、INA 並列。不要把腳位寫死在模組內部。

建議由本模組擁有的欄位（名稱實作時再定，語意要有）：

執行期：模組階段、負載是否接通、本檔開始時間、本檔電氣穩態電流、本檔熱穩電流、電流下垂比例、是否已請求改目標轉速、等待穩調中。

結果：I_cont（安培）、測得時的電阻歐姆、測得時通過的最高轉速、識別是否完成且可信、硬電流天花板（通常小於 INA 飽和的 0.8 安培）。

除錯：本檔序號、最後一次開路電壓、最後一次帶載電壓／電流。這些給畫面與序列埠，不是控制依據。

誰寫誰讀：

- 本模組寫自己結構的全部執行期與結果。
- 畫面、序列埠、日後 MPPT 只讀 I_cont、識別完成、負載接通、階段。
- 目標轉速：本模組在識別中可以改；守護階段不要改轉速。
- 穩調旗標、現在轉速、故障：只讀。
- INA 電壓電流：只讀；發現過流時本模組切斷負載並請求故障鎖定，不在 INA 結構裡塞邏輯。

快閃記憶體：識別成功後可存 I_cont、電阻、通過最高轉速、已識別旗標。開機載入後若「已識別」為真，可跳過識別直接進守護（用常數決定每次開機都重測還是沿用）。電阻常數若與記憶體裡存的電阻不一致，視為設定已改，必須重測，不可沿用舊 I_cont。

## 5. 彈性設定（實作前用常數決定，不必做選單）

下列每一項都要能在改常數後重編即換行為，不要寫死在狀態機裡。

測試電阻

- 歐姆值（已知水泥電阻）。用於核對電壓／電流是否合理，以及可選的熱態內阻。
- 電阻瓦數僅供註解與人為檢查，韌體不必算電阻會不會燒；但帶載功率若明顯超過註解瓦數，可當警告事件，仍以電機電流為切斷依據。

負載 GPIO

- 是否啟用。關閉：視為負載永遠由人手動接上，模組只負責「沒穩調不准開始計時、過流只拉故障、無法自動開路」。此模式較危險，預設應為啟用 GPIO。
- 腳位編號（建議用目前預留給後級的腳，與主動力 PWM 分開；不要占用 START、I2C、測速）。
- 接通為高或為低。上電與故障時的安全電平必須是「斷開」。
- 接通後額外等待（繼電器彈跳、接點穩定）才開始記電氣穩態。
- 切斷後若要量開路電壓，再等電氣穩定才讀 INA。

轉速階梯

- 起始轉速、每檔增量、最高轉速。最高轉速不得高於現有飛車門檻，並留餘量。
- 起始轉速不得低於現有可讀轉速門檻。
- 是否在每檔帶載前先做一次開路電壓（建議開，作為該轉速的 E，也方便事後算內阻）。

時間

- 電氣穩定時間（短）。
- 熱穩定最長時間（長，分鐘級）。
- 熱穩定判定：電流在一段觀察窗內變化小於某比例或某安培，才算打平。
- 檔與檔之間的最短冷卻時間（可為零；預設建議非零）。
- 可選開路快照最長時間（數秒，逾時視為失敗並斷負載）。

電流與下垂

- 硬電流天花板（必須低於 INA 量程 0.8 安培，建議約 0.55～0.65 安培，且可再被「已識別的 I_cont」收緊）。
- 通過：下垂上限（約百分之二到三）。
- 當上限、本檔不通過：下垂上限（約百分之五到十）。
- 絕對下限電流：太小代表負載沒接上或 INA 無效，應失敗而不是當成很耐流。
- 電壓／電流與標稱電阻的一致性檢查（例如算出的等效電阻偏離標稱太多，當接線錯誤）。

識別策略

- 每次開機都測，或記憶體已有且電阻未改則跳過。
- 是否啟用開路快照估銅溫（預設可關，先做下垂法）。
- 識別失敗時：只斷負載並鎖定，不要嘗試自動換下一檔硬闖。
- 守護是否在識別成功前就生效：識別過程本身必須套用硬天花板；I_cont 在尚未產生前，硬天花板就是唯一上限。

畫面與序列埠

- 是否在識別中顯示倒數／本檔轉速／電流／下垂。
- 除錯列印間隔。不要在鎖內印。

沒有的感測器

- 殼溫感測：常數關閉則整條溫度門檻不存在，不假裝有溫度。
- 日後若加溫度，只新增欄位與一個「超溫切斷」，不要改狀態機主幹。

## 6. 狀態機流程

上電：負載 GPIO 設為斷開（若啟用）。載入記憶體。階段＝待機。

按 START 之後（馬達與測速已啟動）：本模組任務活著，但在穩調為假或調參中時，負載保持斷開，不做識別。

A. 待機

- 若設定為沿用舊 I_cont 且記憶體可信：進入守護。
- 若需識別：等穩調為真且調參完成，進入「準備下一檔」（第一檔用起始轉速）。

B. 準備下一檔

- 負載斷開。
- 把目標轉速設成該檔轉速。
- 進入「等定速」。逾時（目標轉不到、故障）→ 失敗鎖定。

C. 等定速

- 只讀穩調旗標。為真後進入「開路取樣」（若該功能關閉則直接「接通負載」）。

D. 開路取樣（可選）

- 確認負載斷開，等電氣穩定，讀電壓當本檔開路電壓、電流應接近零。
- 電流明顯不是零：視為負載 GPIO 黏住或接線錯，失敗鎖定。
- 開路電壓異常高（接近或超過後級耐壓想像值）或異常低：失敗或跳過本檔（常數決定），預設失敗鎖定較安全。

E. 接通負載

- 拉 GPIO 接通，等接點穩定＋電氣穩定。
- 讀電流。超過硬天花板 → 立刻斷開並鎖定。
- 等效電阻與標稱差太多 → 斷開並鎖定。
- 記下「電氣穩態電流」，開始熱穩計時。進入「熱浸泡」。

F. 熱浸泡

- 週期讀電流（及電壓）。任何一次超過硬天花板 → 斷開鎖定。
- 飛車、無脈衝、急停、INA 掉線、穩調變假：斷開，若是急停／故障走既有鎖定；若只是短暫失穩可先斷負載再回到等定速（常數決定，預設走鎖定較單純）。
- 電流在觀察窗內打平：算下垂比例，進入「本檔判定」。
- 熱穩逾時仍未打平：視為不通過（持續發熱），斷開，I_cont 用上一檔通過值；若連第一檔都未通過，I_cont 不成立，鎖定。

G. 本檔判定

- 先斷開負載（進入判定就不該繼續加熱），可選立刻做熱態開路快照。
- 下垂小：本檔通過，更新「目前通過的 I_cont 候選」為本檔熱穩電流。若還有下一檔且下一檔預估電流（用本檔開路電壓與電阻粗估，或用電流約正比轉速外推）不會超過硬天花板：冷卻等待後回到準備下一檔。若預估已超硬天花板或已達最高轉速：識別成功，寫入記憶體，進入守護。
- 下垂中等：識別成功，I_cont＝上一檔通過電流（第一檔就中等則失敗，不要把過熱檔的電流當額定）。進入守護或鎖定（第一檔失敗必鎖定）。
- 下垂大或未打平：同上，更乾脆當失敗檔。

H. 守護（識別成功或沿用舊值之後）

- 負載 GPIO 是否接通改由後級（MPPT／手動）決定；本模組不管誰接通，只看 INA 電流。
- 電流大於 min(I_cont，硬天花板) 持續若干筆（避免雜訊一筆就跳）→ 斷負載＋故障鎖定。
- 本模組不再改目標轉速。

I. 失敗／與整機故障

- 負載必斷。
- 請求與現有急停相同等級的鎖定（主動力 PWM 歸零、階段進故障、需重開機）。
- 畫面顯示安全電流故障碼。

## 7. 安全規則（寫程式時不可省略）

1. 上電、重設、任務尚未跑：GPIO 方向與電平先進入斷開，再做別的初始化。
2. 沒有穩調、調參中、故障中：禁止接通負載。
3. 切斷負載的函式必須可重入、可從急停路徑呼叫、內部先拉腳位再改自己的「已接通」旗標。
4. 識別中途禁止把電阻當可變；軟體沒有「再加一檔更重的負載」。要換電阻只能停機改硬體並改常數。
5. 預估下一檔電流用「本檔電流乘轉速比」或「開路電壓除以（內阻加電阻）」皆可，缺內阻時寧可高估電流、少測一檔，不可低估然後硬上。
6. INA 未在線或資料無效：視同無法保護，不准接通負載；若已接通則切斷並鎖定。
7. 硬天花板永遠生效，包含識別第一秒。I_cont 只能把上限收得更緊，不能放寬過硬天花板。
8. 固定電阻模式的守護在「人把負載手動短路」時仍可能來不及；GPIO 啟用時至少能斷開測試電阻。手動模式必須在文件與畫面標明無自動開路。
9. 不要用計算出來的最大功率點電流當識別目標。識別走階梯＋下垂，不是走最大功率。
10. 與現有飛車、無脈衝看門狗並存，不取代它們。發電側過流是多出來的一條。

## 8. 畫面與除錯（最少）

識別中：階段名稱、目標轉速、現在轉速、是否穩調、負載通斷、電流、本檔下垂、熱穩經過時間。  
守護中：I_cont、硬天花板、即時電流。  
故障：新故障碼文字。  
序列埠：每檔通過／不通過一行（轉速、開路電壓、穩態電流、熱穩電流、下垂、結果）。禁止把 INA 原始值每毫秒印爆。

---

## 9. 建議實作順序（開始寫程式時）

先做負載 GPIO 的安全斷開與急停連動，用假條件確認腳位不會在開機時誤接通。  
再做守護：硬編碼一個很小的電流上限，用手轉或低轉帶載確認會斷開並鎖定。  
再做識別狀態機，熱穩時間先改成幾十秒當乾跑，確認階梯、穩調等待、下垂計算、記憶體寫入。  
最後把熱穩時間改回分鐘級，用真實水泥電阻跑一次完整識別。  
MPPT／降壓占空比等後級，只讀 I_cont 與「守護是否已啟動」，不要複製一套電流限制。

---

## 10. 一句話

安全電流模組＝固定電阻＋定速階梯＋先斷負載再判定下垂，找出保守 I_cont；全程 GPIO 能開路、硬電流低於 INA 飽和；結果進資料中樞給後級當天花板。不是通用額定銘牌，也不是最大功率掃描。
